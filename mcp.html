RGI MCP Server

Score decisions with conservation-bounded learning from Claude Desktop, Cursor, or any MCP client. One install. Zero infrastructure.

Why This Matters

  • Every MCP server today retrieves — documents, data, search results
  • None of them judge whether a decision is good and learn from the outcome
  • This one does: scores against learned centroids, checks a conservation law, compounds accuracy over time
  • Decision #500 is measurably better than #1 — the model didn't change, the decision infrastructure learned

Three capabilities no other MCP server provides:

  • Decision scoring — factor-weighted scoring against centroids shaped by verified outcomes
  • Conservation-bounded learning — won't update judgment from insufficient evidence (α·q·V ≥ θmin)
  • Compounding trajectory — track how accuracy improves; the curve is the proof

2 · Launch

stdio transport (Claude Desktop, Cursor)

$ rgi-mcp-server \ --categories alert_triage,incident_response,threat_detection \ --actions investigate,escalate,mitigate,monitor \ --factors severity,confidence,blast_radius,recurrence,time_sensitivity

HTTP transport (remote / hosted)

$ rgi-mcp-server --http --port 8080 \ --categories alert_triage,incident_response \ --actions investigate,escalate,mitigate \ --factors severity,confidence,blast_radius

Categories, actions, and factors define your decision space. The server creates a ProfileScorer with centroid geometry matching your domain's tensor shape.

What the parameters mean

  • Categories — types of decisions (alert triage, incident response, threat detection). Each develops its own centroid geometry. No cross-contamination.
  • Actions — possible recommendations (investigate, escalate, mitigate). Scorer returns calibrated probabilities across all actions, not just top-1.
  • Factors — dimensions evaluated (severity, confidence, blast radius). Each decision is a point in factor space. Centroids = learned "ideal" position per action per category.
  • Tensor shape — (categories × actions × factors) = centroid geometry. Security with 3×4×5 = 60 centroid values evolving from verified outcomes.

5 · MCP Tools Exposed

⚡
score_decision
Score a decision using cross-graph attention. Returns recommended action, calibrated confidence, full probability distribution, entropy, and confidence gap.
📈
get_trajectory
Retrieve the learning trajectory — how scoring accuracy compounds over verified decisions. Shows the curve from cold-start to current state.
🛡
get_conservation_status
Check whether the system has sufficient evidence to learn. Returns α (coverage), q (quality), V (volume), θ_min (threshold), and the gate status.

The Loop: Score → Verify → Learn → Score Better

  • 1. Score — factor vector → distances to every centroid → calibrated probability distribution
  • 2. Act — agent or human takes the recommended action
  • 3. Verify — outcome confirmed or overridden
  • 4. Conservation check — enough evidence? α·q·V ≥ θmin
  • 5. Learn — gate open → centroids update (ηconfirm = 0.05, ηoverride = 0.01)
  • 6. Score better — next decision scored against centroids shaped by one more verified outcome

This is RGI. The model doesn't change. The decision infrastructure compounds from every verified outcome.

6 · How It Works

7 · The Conservation Law

Every scored decision is bounded by a conservation law — prevents learning from insufficient evidence:

α · q · V ≥ θmin
Coverage × Quality × Volume ≥ Deployment-aware threshold
α
Category coverage
Are you seeing all categories, or just the easy ones?
q
Observed quality
Accuracy on verified decisions within the sliding window
V
Verified volume
How many outcomes have been checked by a human or oracle?
  • Product falls below θmin → scoring continues, centroid updates pause
  • Architectural guarantee: can't learn the wrong lesson from insufficient data
  • ~194 experiments validated this boundary across five domains
# The conservation check inside the MCP server from gae import compute_theta_min threshold = compute_theta_min( alpha=0.72, # coverage across 3 categories volume=47, # verified decisions so far n_categories=3, # alert_triage, incident_response, threat_detection n_actions=4, # investigate, escalate, mitigate, monitor n_factors=5, # severity, confidence, blast_radius, ... ) can_learn = (0.72 * 0.83 * 47) >= threshold # True → centroids update from this outcome # False → scoring continues, learning pauses
